Leaving uv

For a while, I considered that this project would be done when one could run uv add red-dwarf to get it.

I know it would bring some hurdles: find how to build the package, perform checks on test.pypi, then host on pypi...

But in the meantime, I would have learned so much! I would have become such a better programmer!

Then I gave all that up.

The split incident

One morning I tried splitting the source code.

The 600-lines code was easily split into 3 files: a main interface with all user-facing stuff, server.py for route registration and wire.py for parsing and sending requests and responses.

It made sense, right? Easier for other people to read the code, and I would lose nothing except...

except the ability to curl.

curl > uv

Consider an environment where you don't have access to uv, not so uncommon under security restrictions like in corporate environments. Being able to copy/paste the code is a boon.

Or consider that pip/uv can be compromised as in the eMudhra incident.

After all, why wouldn't it be possible? One of the requirements of Red Dwarf was pure Python, no external dependencies. Why waste this?

Requirements? Decently recent Python. Version? Check the comment at the top of the file.

Secure? Sure, ask Claude to review it for all I care. Anyhow, there's no supply chain attack on your paperclip.

Sometimes the reason we can't have nice things is that we're afraid to grab them.

Limitations

Sure, in an actual version control system, you'd want to keep track of the RD version used (and that's if you have to grab it from pypi and can't input it manually because of reasons).

Conclusion

Yeah fuck it we ball. I'll go single-file curl install for RD, and for the two related upcoming projects as well.

My focus is make sure the code is readable top to bottom.

Hope nobody tells me to curl my enthusiasm.
